# Feature Specification: 客户端管理与心跳

**Feature Branch**: `007-client-management-heartbeat`

**Created**: 2026-07-31

**Status**: Draft

**Input**: User description: "左侧账户菜单增加客户端管理；客户端增加心跳；按照行业规则"

## Current deployment mode

TV 不再要求用户输入授权码或在 Web 上批准绑定。首次启动会生成稳定的安装标识，调用自动注册接口，由服务端按 `MAGI_DEFAULT_DEVICE_OWNER_USERNAME`（默认回退 `MAGI_ADMIN_USERNAME`）将设备归属默认账户并签发轮换凭据；随后仅按心跳规则上报。RFC 8628 授权码接口保留为旧版本兼容入口，但不再出现在 TV 或 Web 的默认流程中。

## Scope & Boundaries

本功能让账户所有者从左侧账户菜单查看和管理已绑定的客户端，并通过客户端心跳获得可信、及时的在线状态。它解决“哪些设备仍在使用账户”“设备最后何时活跃”“丢失或废弃设备如何停止访问”三个问题。

**In scope**:

- 左侧账户菜单中的“客户端管理”入口及管理页面。
- 当前账户下客户端的列表、详情摘要、友好名称修改和访问撤销。
- 客户端注册后的周期性心跳、在线状态计算和最后活跃时间展示。
- 客户端离线、网络恢复、凭据失效或访问被撤销时的状态与恢复体验。
- 客户端生命周期事件的安全审计。

**Out of scope**:

- 远程控制客户端、查看实时播放内容或采集观看历史。
- 向客户端推送消息、远程升级、远程卸载或远程关机。
- 精确地理位置、完整 IP 地址、API Key、播放地址等敏感信息的展示。
- 按组织或家庭成员共享管理权限；本期仅由客户端所属账户管理。
- 基于在线状态的计费、并发播放限制或自动删除长期离线客户端。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看账户客户端 (Priority: P1)

已登录的账户所有者从左侧账户菜单进入“客户端管理”，查看属于自己的所有已注册客户端及其当前状态，从而识别正在使用、已经离线或已被撤销的设备。

**Why this priority**: 可发现的管理入口和可信的设备清单是后续心跳状态及安全操作的基础，也是功能的最小可用价值。

**Independent Test**: 为一个账户准备在线、离线和已撤销客户端，从左侧账户菜单进入管理页，验证只显示该账户的客户端，且每项信息与状态正确。

**Acceptance Scenarios**:

1. **Given** 当前账户拥有多个已注册客户端，**When** 用户选择左侧账户菜单中的“客户端管理”，**Then** 页面显示每个客户端的名称、设备类型、平台与应用版本、首次注册时间、最后活跃时间和当前状态。
2. **Given** 当前账户没有已注册客户端，**When** 用户进入客户端管理页，**Then** 页面显示明确的空状态，并提示 TV 启动后会自动登记、无需输入授权码。
3. **Given** 系统中存在其他账户的客户端，**When** 当前用户查看客户端管理页，**Then** 其他账户的客户端及其任何信息均不可见。
4. **Given** 客户端数量超过单页容量，**When** 用户浏览列表，**Then** 可以继续查看全部客户端，且状态与最近活跃时间排序保持稳定。

---

### User Story 2 - 通过心跳获知在线状态 (Priority: P1)

已授权客户端在运行期间定期报告存活状态。账户所有者无需手动刷新设备或猜测状态，即可在合理延迟内看到客户端上线、持续在线和离线。

**Why this priority**: 心跳是“客户端管理”区别于静态设备清单的核心价值，并为故障诊断和访问安全提供事实依据。

**Independent Test**: 启动一个已授权客户端并持续发送心跳，随后中断连接再恢复；验证状态按规定从在线变为离线并重新变为在线，最后活跃时间只向前推进。

**Acceptance Scenarios**:

1. **Given** 已授权客户端成功注册，**When** 它首次成功报告心跳，**Then** 客户端状态变为在线，最后活跃时间使用服务端接收时间更新。
2. **Given** 在线客户端按期持续报告心跳，**When** 用户查看或刷新管理页，**Then** 客户端保持在线，最后活跃时间单调递增。
3. **Given** 在线客户端连续 150 秒没有成功心跳，**When** 用户查看其状态，**Then** 客户端显示为离线，并保留最后一次成功活跃时间。
4. **Given** 离线客户端恢复网络并再次成功报告心跳，**When** 状态更新完成，**Then** 客户端重新显示为在线，无需创建重复客户端记录。
5. **Given** 客户端本地时钟错误或重复发送同一次报告，**When** 系统接收心跳，**Then** 最后活跃时间不会倒退，也不会产生重复客户端。

---

### User Story 3 - 识别并撤销客户端 (Priority: P2)

账户所有者可为客户端设置易识别名称，并撤销丢失、出售或不再使用设备的访问权限，以维护账户安全。

**Why this priority**: 列表只有配合识别和撤销能力才能形成完整的客户端生命周期管理，但不阻塞只读清单和在线状态的首期价值。

**Independent Test**: 对一个在线客户端修改名称并撤销访问，验证名称保留、状态立即变为已撤销、后续心跳被拒绝且客户端获得可恢复提示。

**Acceptance Scenarios**:

1. **Given** 当前账户拥有某客户端，**When** 用户将其名称修改为有效的新名称，**Then** 新名称被保存并在后续访问中一致显示。
2. **Given** 用户准备撤销一个客户端，**When** 用户发起撤销，**Then** 系统在执行前明确说明影响并要求确认。
3. **Given** 用户确认撤销，**When** 操作成功，**Then** 客户端立即标记为已撤销，撤销时间被记录，原有访问资格不再有效。
4. **Given** 已撤销客户端再次报告心跳或请求受保护内容，**When** 系统验证其资格，**Then** 请求被拒绝，且客户端记录不得恢复为在线。
5. **Given** 用户尝试修改或撤销不属于自己的客户端，**When** 请求被处理，**Then** 操作被拒绝且不会泄露目标客户端是否存在。

---

### User Story 4 - 客户端从中断或撤销中恢复 (Priority: P2)

客户端在临时断网时继续提供可理解的本地状态并在网络恢复后自动恢复心跳；在凭据失效时自动重新登记到默认账户，在凭据被撤销时停止重试并提示管理员处理，而不是无限重试。

**Why this priority**: 行业标准的心跳不能以耗电、请求风暴或不可恢复错误为代价，TV 客户端尤其需要只靠遥控器完成恢复。

**Independent Test**: 在客户端运行时依次模拟断网、恢复网络、凭据失效和访问被撤销，验证退避、恢复、停止重试和重新配置流程均符合预期。

**Acceptance Scenarios**:

1. **Given** 客户端临时断网，**When** 心跳失败，**Then** 客户端不会退出或高频重试，并在网络恢复后自动重新报告心跳。
2. **Given** 客户端凭据失效，**When** 心跳或刷新被拒绝，**Then** 客户端清除旧凭据并自动尝试一次默认账户登记；若设备已撤销则停止重试并显示明确提示。
3. **Given** Android TV 客户端显示自动登记失败提示，**When** 用户仅使用方向键、OK 和 Back，**Then** 可以重试登记或返回安全页面。

### Edge Cases

- 同一物理设备因重装应用或清除数据而失去原客户端身份时，必须作为新客户端注册，不得猜测并占用旧身份；旧记录保留供账户所有者识别和撤销。
- 多个客户端使用相同型号、默认名称或网络地址时，仍以各自稳定标识区分，状态不得互相覆盖。
- 心跳乱序、重复或并发到达时，最后活跃时间只能向前推进，单个客户端仍只有一个生命周期状态。
- 客户端在在线阈值边界附近报告时，以服务端最后成功接收时间统一判定，避免客户端本地时间差异导致状态抖动。
- 用户在撤销操作与心跳同时发生时，撤销优先；成功撤销后的任何心跳都不能恢复访问。
- 管理页加载失败或状态暂时无法刷新时，保留最近一次已知数据并明确标记其更新时间，不把未知误报为在线。
- 名称为空、仅空白、过长或包含不可显示字符时，修改被拒绝并给出可操作提示；重复名称允许存在，但稳定标识和设备摘要仍可帮助区分。
- 心跳频率异常高时，系统保护服务可用性并返回一致结果，不产生重复审计事件或破坏客户端状态。

### Android TV Interaction & Recovery *(mandatory when TV is in scope)*

- **Focus entry**: 凭据失效或客户端被撤销的提示出现时，初始焦点落在“重新配置”主操作；进入配置页后落在第一个待处理字段。
- **Directional map**: 上/下在提示操作与配置字段间按视觉顺序移动；左/右仅在同一操作组或可编辑控件内移动；任何可见操作均可由方向键到达，不存在焦点死区。
- **Focus restoration**: 临时网络错误提示关闭后，焦点恢复到此前的频道或播放器；取消重新配置后返回触发提示前的安全页面，不恢复到已失效的播放操作。
- **Back hierarchy**: 最上层授权提示或配置弹层 → 信息层/侧栏 → 上一页面 → 退出应用。访问已撤销时，Back 不得绕过重新授权要求进入受保护内容。
- **Playback lifecycle**: 心跳独立于播放器状态，不创建或持有播放器；换台、缓冲和线路切换不应重置客户端身份或制造额外客户端。应用退到后台后不维持前台频率，恢复前台时立即补充一次合规心跳。
- **Recovery actions**: 断网时提供重试并自动采用有上限的退避；未授权或已撤销时停止自动重试并提供重新配置；服务暂时不可用时保留安全的本地界面且不得展示敏感诊断数据。
- **10-foot UI**: 关键正文至少 16sp、辅助正文至少 14sp；交互目标至少 48dp；内容位于 TV 安全区；焦点同时使用轮廓、缩放或明度等非单一颜色反馈。
- **Device acceptance**: 在 Android TV 模拟器及至少一台真实遥控器设备验证应用启动心跳、前后台切换、断网与恢复、401/撤销、重新配置、快速换台期间的身份稳定性，以及弹层的焦点与 Back 恢复。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在已登录用户的左侧账户菜单中提供清晰、唯一的“客户端管理”入口，并保持与其他账户设置入口一致的选中与导航反馈。
- **FR-002**: 系统 MUST 仅允许账户所有者查看和管理归属于该账户的客户端；未登录、跨账户或已失效会话不得读取任何客户端详情。
- **FR-003**: 客户端列表 MUST 展示友好名称、稳定的非敏感识别摘要、设备类型、平台与应用版本、首次注册时间、最后活跃时间，以及“在线”“离线”“已撤销”之一的明确状态。
- **FR-004**: 系统 MUST 默认按状态优先级和最近活跃时间展示客户端：在线在前，其后为离线，已撤销在后；同一状态内最近活跃者优先。
- **FR-005**: 系统 MUST 为无客户端、加载中、加载失败和数据已过期分别提供可区分、可恢复的页面状态。
- **FR-006**: 每个已注册客户端 MUST 具有不可由其他客户端冒用的稳定身份，并绑定唯一所属账户；重新安装或清除本地身份后必须重新注册为新客户端。
- **FR-007**: 已授权且处于运行状态的客户端 MUST 默认每 60 秒报告一次心跳；应用从后台恢复到前台或网络恢复时，应立即尝试一次心跳，而不是等待完整周期。
- **FR-008**: 系统 MUST 以服务端成功接收心跳的时间更新最后活跃时间，不信任客户端提交的本地时间作为在线判定依据。
- **FR-009**: 客户端最后一次成功心跳距当前服务端时间不超过 150 秒时 MUST 判为在线；超过 150 秒时 MUST 判为离线；已撤销状态始终优先于时间判定。
- **FR-010**: 重复、乱序或并发心跳 MUST 幂等处理：不得创建重复客户端，最后活跃时间不得倒退，已撤销客户端不得恢复为在线。
- **FR-011**: 临时心跳失败 MUST 使用带随机扰动且有上限的逐步退避，避免请求风暴；一次临时失败不得立即把本地体验当作永久未授权。
- **FR-012**: 心跳资格无效或过期时，客户端 MUST 清除旧凭据并自动尝试一次默认账户登记；已撤销客户端 MUST 被拒绝且不得通过自动登记复活。
- **FR-013**: 账户所有者 MUST 能修改所属客户端的友好名称；名称去除首尾空白后长度须为 1–64 个可显示字符。
- **FR-014**: 账户所有者 MUST 能撤销所属客户端；系统 MUST 在确认后立即使其访问资格失效，并记录操作者、目标客户端、发生时间和结果。
- **FR-015**: 撤销是安全操作且 MUST 优先于同时发生的心跳；已撤销客户端不得通过自动登记恢复原资格，管理员需先按安全流程解除终态后才可重新接入。
- **FR-016**: 系统 MUST 记录客户端注册、名称变更、撤销、拒绝已撤销客户端等安全相关生命周期事件，并提供可关联的请求上下文；常规成功心跳不得产生噪声级逐次审计记录。
- **FR-017**: 管理页面、用户可见错误、日志、审计和诊断信息 MUST NOT 包含 API Key、访问令牌、完整播放地址或其他可用于冒充客户端的秘密。
- **FR-018**: 客户端管理与心跳 MUST 在 10,000 个已注册客户端、1,000 个同时在线客户端的产品规模下维持本规格的状态及时性和用户体验指标。
- **FR-019**: Android TV 客户端 MUST 仅靠方向键、OK 和 Back 完成自动登记失败/已撤销提示、重试和返回流程，并满足本规格定义的焦点、Back、可读性及实机验收要求。
- **FR-020**: 本功能 MUST NOT 收集或展示精确位置、观看历史、完整 IP 地址或当前播放内容；未来新增此类数据需独立规格与隐私评审。

### Key Entities *(include if feature involves data)*

- **Client**: 代表绑定到一个账户的设备或应用实例；包含稳定身份、所属账户、友好名称、设备类型、平台、应用版本、注册时间、最后活跃时间和生命周期状态。一个账户可拥有多个客户端，一个客户端只能属于一个账户。
- **Client Credential**: 代表客户端证明身份和账户归属的访问资格；具有有效、失效或撤销状态。秘密值不可在管理页面、日志或诊断中展示。
- **Heartbeat Observation**: 代表系统成功接收某客户端存活报告的事实；包含服务端接收时间及用于追踪问题的非敏感上下文，用于推进最后活跃时间和派生在线状态。
- **Client Audit Event**: 代表客户端生命周期中的安全相关动作；包含事件类型、目标客户端、操作者或来源、发生时间、结果和关联上下文，不保存凭据或播放秘密。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 95% 的已登录用户能在 30 秒内从左侧账户菜单找到客户端管理页，并正确识别最近使用的客户端。
- **SC-002**: 在网络正常时，95% 的新启动或恢复前台客户端在 10 秒内显示为在线，99% 在 30 秒内显示为在线。
- **SC-003**: 停止心跳的客户端在最后一次成功报告后的 180 秒内对用户显示为离线，且状态误报率低于 1%。
- **SC-004**: 账户所有者可在 60 秒内完成识别、确认和撤销一个客户端；撤销成功后 5 秒内，该客户端的后续受保护操作全部被拒绝。
- **SC-005**: 在 10,000 个已注册客户端、1,000 个同时在线客户端的验收负载下，95% 的用户在 2 秒内看到客户端列表及状态，且状态及时性仍满足 SC-002 与 SC-003。
- **SC-006**: 重复、乱序、并发心跳以及撤销竞态测试中，不出现重复客户端、最后活跃时间倒退或已撤销客户端重新上线，正确率达到 100%。
- **SC-007**: 安全检查中，跨账户读取和修改成功次数为 0；管理页面、错误、日志与审计样本中发现的凭据、完整播放地址或其他秘密数量为 0。
- **SC-008**: Android TV 的断网恢复、401、撤销和重新配置验收场景在模拟器与真实遥控器设备上 100% 可仅用 D-pad、OK 和 Back 完成，无焦点死区或只能退出应用的错误状态。
- **SC-009**: 内部可用性测试中，至少 90% 的参与者首次尝试即可正确解释“在线”“离线”“已撤销”的差异，并完成目标客户端撤销。

## Assumptions

- “客户端”指绑定到当前账户的设备或应用实例，包括 Android TV；不指 OAuth、开发者平台或第三方集成中的 API 客户端。
- 现有账户登录、客户端注册和访问凭据机制继续作为身份基础；本功能扩展生命周期管理，不重新设计账户认证。
- 60 秒心跳周期与 150 秒在线窗口作为首期产品默认值，兼顾状态及时性、短暂网络抖动和客户端资源消耗；行业并无适用于所有应用客户端的唯一固定周期，后续可依据真实运行指标调整，但任一环境内必须采用一致规则。
- 在线状态是由最后一次成功心跳派生的运行状态，不等同于正在播放、应用始终位于前台或设备物理开机状态。
- 应用处于后台或被操作系统暂停时可降低或停止心跳，因此账户页可能显示离线；恢复前台时通过立即心跳快速纠正。
- 已撤销记录保留用于安全追溯和设备识别，不在本期自动删除；数据保留期遵循项目统一的账户与安全审计政策。
- 列表允许重复友好名称，因为家庭中可能存在同型号设备；稳定的非敏感识别摘要用于辅助区分。
- Web 管理端沿用现有账户权限、导航语言和设计系统；Android TV 沿用现有配置并自动登记到默认账户。

## Dependencies

- 现有账户认证与账户所有权判断必须可用。
- 客户端必须在心跳前完成自动注册并取得与默认账户绑定的有效资格。
- 所有参与客户端需要遵循同一客户端身份、撤销和在线状态语义。
- 运行环境需要可靠的服务端时间来源；客户端本地时钟不参与权威在线判定。
